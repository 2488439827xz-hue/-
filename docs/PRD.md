# AI GitHub Radar · 产品需求发现包

## 1. 执行摘要

- **产品阶段**：可运行 MVP / 7 天实验前。
- **主要用户**：正在学习并实践 AI 产品经理、希望形成作品集的个人用户。
- **核心任务**：每天在 30 分钟内发现并判断少量 Agent、Agent Skill 与 Agent 工作流项目的实际价值。
- **价值主张**：将“别人推荐 + GitHub 手动搜索”的偶发发现，变成有证据、有解释、可继续行动的每日决策支持。
- **准备度**：Prototype ready；尚未达到 PRD ready，因为真实使用数据、飞书密钥配置和完整评测集仍待完成。

## 3. 问题与用户

**可观察问题**：当前项目发现依赖他人先推荐，随后手动搜索；发现后还需要自行判断项目解决的问题、Star 背后的可能原因，以及与学习/工作的关系。

**问题陈述**：作为正在学习 AI 产品经理的用户，在希望持续理解 Agent 生态时，很难稳定发现并快速判断真正有用的项目，导致项目容易停留在“看过或收藏”，难以转化为产品洞察、知识和作品集。

**JTBD**：当我每天了解 Agent 生态时，我希望在 30 分钟内看到少量有证据的候选项目并完成价值判断，以便决定哪些忽略、哪些以后再看、哪些值得深入分析或做成作品。

**当前替代方案**：他人推荐、GitHub 手动搜索、Star 排序、Awesome 聚合列表。

## 4. 结果、指标和非目标

### 用户结果

- 3 分钟左右对单个项目形成“现在有用 / 未来有用 / 无关”的初步判断。
- 每周识别至少一个值得深入分析的项目（待验证目标）。
- 四周内完成至少一份可进入作品集的产品分析或衍生方案（待验证目标）。

### 指标

- **领先指标**：日报读完率、仓库点击率、完成价值标记率。
- **结果指标**：深挖选择率、学习笔记数、作品集产出数。
- **质量指标**：推荐有用率、事实错误率、不受支持断言率、重复率。
- **护栏指标**：实际阅读时间、API 请求数、发送失败率、低相关项目率。

### 停止或调整条件

- 连续 7 天中 4 天以上未读完：减少项目或改发送时段。
- 有用率低于 50%：重做搜索范围与相关性权重。
- 两周没有任何深挖选择：验证项目质量和目标是否真实。
- 不受支持的关键断言超过 5%：暂停自动投递并修复评估契约。

### 非目标

- 覆盖全部 AI 新闻或全部 GitHub 热门项目。
- 将 Star 数等同于项目质量。
- 自动克隆或运行未知仓库代码。
- 未经用户选择就为全部项目生成长篇分析。
- MVP 阶段开发复杂的飞书应用机器人或推荐模型。

## 5. MVP 用户旅程

1. 07:40 触发自动化。
2. 通过 GitHub Search API 获取候选并读取有限 README。
3. 确定性规则去重、预筛并保存事实快照。
4. AI 按证据契约评估，选出 3–5 个项目。
5. 校验 JSON、生成 Markdown 并通过飞书发送。
6. 用户点击仓库，做“现在/未来/无关/深挖”判断。
7. 若选“深挖”，进入单独的 AI 产品拆解与作品集流程。
8. 若采集、模型或投递失败，GitHub Actions 标记失败并保留 14 天诊断 Artifact。

## 6. 核心需求与验收

| ID | 需求 | 优先级 | 可验收标准 |
|---|---|---:|---|
| P1 | 采集核心主题候选 | Must | 查询 Agent、Agent Skill、Workflow 和聚合项目并去重 |
| P2 | 事实预筛 | Must | 保存仓库 URL、Star、更新时间、License、README 信号与评分分项 |
| P3 | AI 价值评估 | Must | 每个项目回答用途、问题、独特性、价值、个人作用、行动与风险 |
| P4 | 证据控制 | Must | Star 原因只能写成有依据的假设；输出置信度 |
| P5 | 飞书投递 | Must | 使用加密 Secret 中的 Webhook，每次载荷受字节限制并支持拆分 |
| P6 | 安全 | Must | `.env` 被 Git 忽略，日志不打印密钥，支持签名校验 |
| P7 | 定时运行 | Must | Asia/Shanghai 每天 07:40 触发 |
| P8 | 无人值守云运行 | Must | 桌面应用与个人电脑关闭时，GitHub Actions 仍可执行 |
| P9 | 深挖反馈 | Should | 用户可从日报选择项目进入后续分析；MVP 可先人工回复 |
| P10 | 自动个性化 | Later | 至少 20 条真实反馈后再调整权重 |

## 7. AI 行为契约

| 能力 | 输入 | 输出 | 不允许失败 | 人工控制 | 降级 |
|---|---|---|---|---|---|
| 项目选择 | 元数据、README、预筛分 | 3–5 个推荐 | 因 Star 高就虚构价值 | 用户决定是否点击/深挖 | 只发确定性候选并标注弱日报 |
| 产品分析 | 仓库证据 | 问题、用户、价值、差异 | 把推测写成事实 | 用户可纠正 | 降低置信度或不作判断 |
| Star 原因分析 | Star、年龄、文档、定位等 | 假设及支持信号 | 声称未经证实的因果 | 用户可要求核查外部传播 | 标记未知 |
| 个性化建议 | 用户目标与主题 | 现在/未来价值、下一动作 | 替用户决定必须学习 | 用户选择深挖 | 提供中性浏览建议 |

AI 是必要的，因为“项目对个人有什么启发”和“解决了什么产品问题”需要语义判断；但采集、去重、字节限制、分数计算和结构校验使用确定性代码更可靠。

## 8. 数据、安全与版权

- 只读取公开 GitHub 仓库元数据和 README 片段。
- 保存 90 天快照用于趋势计算；不采集个人身份数据。
- 引用仓库 URL，摘要使用改写，不复制大段 README。
- 不自动运行仓库代码，避免供应链和恶意脚本风险。
- 密钥只保存在本地 `.env`，不得进入 Git、日报或模型上下文。
- GitHub 返回缺失 License 时明确提示“许可未知”，不得默认可商用。
