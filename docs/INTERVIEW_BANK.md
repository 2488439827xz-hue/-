# AI GitHub Radar 面试题库

使用方法：不要背答案。先用 60–90 秒回答“结论—依据—权衡—验证”，再结合本项目举例。括号内是面试官期望听到的关键词，不是标准台词。

## 一、产品与用户

1. 你为什么要做这个产品，而不是订阅现有 GitHub Trending？（目标用户、情境、替代方案、差异）
2. 用户说“想看热门项目”，你如何挖到真实需求？（解决方案表达、JTBD、最近一次行为）
3. 这个产品的北极星指标是什么？为什么不是推送量？（完成价值判断、深挖与产出）
4. 你如何验证用户真的愿意每天花 30 分钟？（意愿不是行为、7 天实验）
5. 为什么每天只推荐 3–5 个？（注意力预算、质量、读完率）
6. 如果用户点击很多但从不深挖，产品成功了吗？（虚荣指标、结果指标）
7. 你如何定义“对用户有价值”？（当下、未来、学习、工作、作品集）
8. 为什么先做单用户产品仍有产品价值？（高密度学习、验证机制、不可伪造市场规模）
9. MVP 中你主动不做什么？为什么？（登录、后台、复杂机器人、自动运行代码）
10. 什么证据会让你停止这个项目？（可证伪条件）

## 二、范围与优先级

11. 为什么从广泛 AI 调整为 Agent、Agent Skill 和 Workflow？（用户纠正、需求台账）
12. 如何避免只推荐用户已知主题的信息茧房？（探索/利用）
13. 如何用 RICE、MoSCoW 或风险优先级排功能？本项目更适合哪个？（单用户、风险假设）
14. 为什么“主题相关”不应该变成每天凑数配额？（质量阈值）
15. 如果当天没有三个高质量项目怎么办？（宁缺毋滥、弱日报、降级）

## 三、Agent、Skill 与 Workflow

16. Agent、Workflow、Tool、MCP 和 Agent Skill 分别是什么？
17. 这个系统为什么主要是 Workflow，而不是自主 Agent？（路径可预定、可测试）
18. 什么情况下你会把它升级成 Agent？（动态规划与工具选择的增益）
19. Agent Skill 的产品价值是什么？（复用、按需加载、组织上下文）
20. Skill 与普通提示词模板有什么不同？（资源、脚本、操作流程、生命周期）
21. MCP 解决的是什么问题？它是否等同于 Skill？（连接协议 vs 能力包）
22. 多 Agent 一定比单 Agent 好吗？（协调成本、错误传播、评测）
23. 如何评估一个 Agent 框架是否值得采用？（问题适配、可观察性、生态、锁定、成本）
24. Agent 的“自主性”为什么是风险预算，而不是越高越好？（权限与后果）

## 四、数据与推荐

25. GitHub 候选项目从哪里来？（Search API、聚合仓库、元数据、README）
26. GitHub Trending 没有官方 API 时你怎么设计？（合法数据源、代理指标、可解释限制）
27. 为什么不能直接按 Star 排序？（累计偏差、年龄、传播、适配度）
28. Star velocity 如何计算？首日怎么办？（历史快照、代理标注）
29. 召回和排序有什么区别？哪个错误更严重？（漏召回 vs 错排序）
30. 如何处理新项目的冷启动？（内容特征、探索位、置信度）
31. 如何识别刷 Star？（异常增速、fork/使用信号、外部证据；只能判风险）
32. 聚合仓库为什么既有价值又有风险？（高召回、维护偏差、收录不等于质量）
33. 如何去重同一项目的不同来源？（稳定 repo identity）
34. 用户反馈很少时如何个性化？（明确偏好、少量行为、不要过拟合）
35. 如何防止反馈回路只强化热门项目？（多样性、探索、时间衰减）

## 五、AI 设计与提示词

36. 哪些步骤必须用 AI，哪些不该用 AI？（语义判断 vs 确定性计算）
37. 如何减少模型对 README 的幻觉？（grounding、引用、结构化输出、拒答）
38. 为什么 JSON Schema/程序校验不能解决全部幻觉？（结构正确不等于语义正确）
39. 如何分析“为什么 Star 多”而不制造因果？（假设、信号、置信度、外部验证）
40. 模型把 README 中的恶意指令当成任务怎么办？（不可信输入、指令层级、隔离）
41. 为什么使用两层评分？（候选效率与用户价值是不同目标）
42. LLM-as-a-judge 有什么问题？（偏差、漂移、自洽不等于正确）
43. 如何让日报风格稳定但不模板化？（行为契约、字段、允许变化范围）
44. 如果模型服务不可用，如何降级？（确定性榜单、本地报告、不发送错误分析）
45. 如何控制 Token 成本？（先筛后读、截断 README、缓存、少量候选）

## 六、评测与实验

46. 你会如何构建这个产品的评测集？（正例、反例、边界、对抗、恢复）
47. 覆盖率与不受支持断言率为什么要分开测？（遗漏与编造是不同错误）
48. 什么是离线评测，什么是线上评测？（固定案例 vs 真实行为）
49. 如何判断新提示词真的比旧提示词好？（固定集回归、盲评、显著差异）
50. 推荐有用率怎么标注？（用户情境、等级定义、一致性）
51. 如何做 A/B 测试？单用户阶段有什么替代方法？（交替日、时间序列、质性复盘）
52. 最严重的失败是什么？（密钥泄露、恶意代码、事实捏造）
53. 为什么发送成功率不能代表产品成功？（系统健康 vs 用户价值）
54. 评分一致性高是否一定好？（稳定地错、探索不足）

## 七、系统设计与工程

55. 画出端到端架构并说明每个边界。（采集、预筛、AI、校验、投递、反馈）
56. 如何处理 GitHub API 限流？（认证、缓存、退避、请求预算）
57. 什么是幂等？如何避免日报重复发送？（日期键、发送回执）
58. 如何观察和排查一次失败运行？（结构化日志、阶段状态、脱敏）
59. 为什么保存原始候选和评估 JSON？（可追溯、回归、审计）
60. 如何拆分超过飞书限制的消息？（按 UTF-8 字节、段落边界）
61. 如果规模扩展到一万用户，架构首先哪里会变？（队列、用户画像、批处理、配额）
62. 如何控制并发而不触发 GitHub 二级限流？（速率限制、队列、退避）

## 八、安全、合规与商业化

63. Webhook 和 Token 应如何保存？（环境变量、秘密管理、最小权限、轮换）
64. 为什么不能自动运行推荐仓库？（供应链、恶意代码、权限）
65. README 的版权和仓库许可证分别影响什么？（摘要引用 vs 代码复用）
66. 缺失 License 时可以商用吗？（不能默认授权）
67. 如果日报面向企业，新增哪些风险？（内部数据、权限、审计、SLA）
68. 这个产品如何商业化？（专业主题、团队情报、深度报告；先验证支付问题）
69. 竞争壁垒是什么？（反馈数据、评测体系、工作流融合，而非单一提示词）
70. 如何证明 AI 成本带来了增量价值？（与规则基线对比）

## 回答自检

每次回答前快速检查：

1. 我说的是事实、假设还是决策？
2. 我是否说明了用户和情境？
3. 我是否给出了权衡，而不是只列优点？
4. 我如何用最低成本验证？
5. 如果失败，系统如何恢复或由人接管？
