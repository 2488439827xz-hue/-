## 今日项目

### 1. sickn33/agentic-awesome-skills · 86.0/100
https://github.com/sickn33/agentic-awesome-skills

- **一句话**：AAS Core 是本地优先的 agent 控制平面，提供完整技能目录发现、agent 自主选择、栈验证与规划，包含 2005+ 技能、CLI、本地 MCP、目录与插件。
- **解决的问题**：coding agent 面对海量技能时缺乏选择与验证机制，导致栈不稳定、难以复现。
- **独特之处**：强调 'agent 拥有选择'，通过只读 compose_stack 工具在内存中验证，生成不可变计划，区别于其他 '推荐' 型目录。
- **为什么有价值**：为 AI 产品经理提供技能生态的底层架构视角，理解 agent 如何自主决策与验证，是设计面向 agent 的工作流的关键参考。
- **与你的关系**：当下：可作为学习 agent 技能管理的案例；未来：设计类似控制平面或评估技能生态时的基准。
- **建议动作**：30 分钟内：阅读 AAS Core 预览指南，安装 aas CLI，尝试列出本地目录并生成一个栈计划。
- **Star 原因假设**：技能生态爆发，开发者需要统一管理工具（支持：2019 技能数据增长）；MCP 与 agent 工作流热度带动（支持：话题包含 mcp、claude-code）；标榜社区项目与广泛兼容性吸引关注（支持：README 突出独立性与非附属声明）
- **风险/限制**：大型目录可能质量参差，需要额外过滤；核心功能仍标记实验性，稳定性待验证
- **判断置信度**：高

- **风险/限制**：面向特定领域，可能不适合非数据用户；open_issues 较多，部分技能可能未完善

https://github.com/hraness/atet

- **一句话**：Atet 是面向 coding agent 的本地创意媒体生成与视频编辑工具包，通过 Bun CLI 和本地媒体引擎，使 agent 能生成图像、视频、语音并编辑导出。

## 今日重点

重点拆解 agentic-awesome-skills：目标用户是使用 coding agent（如 Codex、Claude）的开发者与团队，他们需要从庞大技能库中选择可靠技能。待办任务是：无缝发现、选择、验证并部署技能栈到项目中。旧替代方案：手动浏览 GitHub 话题或静态列表，缺乏权威验证，导致技能不兼容或失效。价值主张：提供本地、agent 自主的控制平面，确保技能选择可复现且有不可变计划，降低栈维护成本。AI 是否必要：是，因为 agent 需要自主判断哪些技能适用，AI 驱动搜索与验证。核心指标：技能栈采纳率、计划生成速度、栈失败率。主要风险：技能目录质量参差，代理选择可能出错；核心功能仍实验性。作品集衍生想法：基于此项目，设计一个概念验证：针对特定编码任务，比较使用 AAS 前后的 agent 成功率与耗时，写一篇案例分析。
