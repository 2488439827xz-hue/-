### 1. kajisho5/ffmpeg-skill · 82.0/100
https://github.com/kajisho5/ffmpeg-skill

- **独特之处**：强调 no cloud / no API keys / Python 标准库，并提供机器可读契约 + MCP，把媒体处理这种重命令行任务变成 Agent 可规划、可校验的结构化工具集。
- **为什么有价值**：对 AI 产品经理而言，它是“如何为 Agent 设计工具契约与自检闭环”的具体样本：工具描述、参数约束、输出测量、稳定/实验分层都能直接借鉴。
- **与你的关系**：当下用途：30 分钟内读它的工具契约与 MCP 设计，理解 Agent 工具应该怎样描述输入输出；未来用途：做视频运营/内容自动化类 Agent 产品时，可作为“本地处理 + Agent 编排”的参考架构。
- **建议动作**：打开仓库，只看 docs 中的 tools 列表和 MCP 部分，摘录 3 个工具的输入/输出契约，写成一页“Agent 工具契约清单”笔记。
- **Star 原因假设**：假设：Star 快速增长与“给编码 Agent 加视频编辑能力”这一高频创作者场景契合有关，支持信号是 3.95 天约 1519 Star 的观测增量；假设：本地、无 API key、MIT 降低了试用门槛，吸引创作者和开发者转发，支持信号是 README 强调 privacy 与 npx 快速安装
- **风险/限制**：42 个工具中仅 12 个标注稳定，apply/recovery 类操作可能不稳定，生产使用需先验证；视频处理对本地 FFmpeg 版本与系统依赖敏感，CI 覆盖不等于用户环境全覆盖；Star 增长过快可能带来预期膨胀，实际稳定性仍需自行验证
- **判断置信度**：中

## 今日重点

重点项目：kajisho5/ffmpeg-skill。目标用户：需要批量产出短视频的内容创作者与做内容自动化的开发者。待办任务：把一段素材剪辑、加字幕、重构图并导出到指定平台规格，且要确认输出结果符合预期。旧替代方案：手工在剪映/After Effects 操作，或付费 SaaS，或让 Agent 直接拼 FFmpeg 命令但缺少校验。价值主张：本地、无云、无 API key，用机器可读契约把 42 个工具暴露给 Agent，并让 Agent 在输出后自检（时长、分辨率、响度等）。AI 是否必要：必要——参数组合与平台规格多，Agent 的价值在于选择工具、编排步骤、读取测量结果并修正。核心指标：任务一次成功率、输出规格命中率、人工修正次数、平均完成时间。主要风险：稳定性分层（12 稳定 vs 42 总数）、用户环境差异、Star 热度掩盖真实缺陷。作品集衍生想法：做一份“Agent 工具契约设计 checklist”，以 ffmpeg-skill 为案例，对比它如何描述参数、如何处理失败与自检，产出一页可复用的产品规范。
