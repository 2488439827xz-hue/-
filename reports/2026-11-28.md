### 1. kajisho5/ffmpeg-skill · 80.0/100
https://github.com/kajisho5/ffmpeg-skill

- **一句话**：给编码 Agent 使用的本地视频编辑技能：42 个 FFmpeg 工具、机器可读契约与 MCP server，强调无需云和 API Key。

- **为什么有价值**：对 AI 产品经理而言，它是理解“Agent Skill 不是提示词，而是带输入输出契约与验证步骤的能力封装”的高质量样本，可迁移到其他垂直工具。
- **与你的关系**：当下可用于观察如何为 Agent 设计工具边界与验收指标；未来可借鉴到内容生产、电商素材后处理等 Agent 工作流产品设计。
- **建议动作**：花 25 分钟阅读 README 的 Quick Start、Tools 与 Security 小节，列出 3 个“工具契约 + 输出验证”设计点，并写一段它适合/不适合的产品场景判断。
- **Star 原因假设**：短期 Star 增长可能来自 AI 编码 Agent 用户对本地视频处理这一明确任务的集中需求，支持信号是 6 天内约 2652 Star 的观测增量；可能受益于 Claude Code/Cursor/MCP 生态传播，README 同时覆盖多个 Agent 客户端；视频编辑是高频演示场景，容易通过短视频或 X 传播，但该原因仅为假设
- **风险/限制**：42 个工具中仅少部分标为稳定，功能广度可能掩盖成熟度差异；视频处理涉及本地文件与外部二进制 FFmpeg，权限与安全边界需要用户自行审查；Star 增速极快但项目创建时间较短，长期维护仍待观察
- **判断置信度**：medium-high

## 今日重点

重点项目：kajisho5/ffmpeg-skill。目标用户是使用 Claude Code、Cursor 或 Codex 处理视频的内容创作者与开发者；待办任务是把剪辑、字幕、重构图、响度标准化和平台导出变成可重复的 Agent 工作流。旧替代方案是手动操作剪辑软件、让 Agent 生成不可验证的 FFmpeg 命令，或调用云端视频 API。价值主张是本地、无 API Key、带机器可读契约并让 Agent 检查输出。AI 必要性中等偏高：FFmpeg 本身确定性强，但自然语言到工具参数选择、失败后调整和多步编排需要 Agent；若只是固定转码，则 AI 不必要。核心指标可设为任务一次成功率、输出验证通过率、人工返工次数和单任务耗时。主要风险是工具过多导致稳定能力被稀释、本地文件权限边界不清、依赖 FFmpeg 环境差异。作品集衍生想法：做一页“Agent 视频后处理技能评测”，用同一段素材比较纯提示词、手工脚本和该技能三条路径的成功率与返工点。
