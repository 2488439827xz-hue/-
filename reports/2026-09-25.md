## 今日项目

### 1. sickn33/agentic-awesome-skills · 82.0/100
https://github.com/sickn33/agentic-awesome-skills

- **一句话**：AAS Core 是把 2445+ agent skills 组织成本地目录，让 Codex/Claude 自主检索、选择、校验并生成可审阅计划的本地控制面。
- **解决的问题**：Agent Skill 数量爆炸后，人很难判断哪些技能适合当前项目、组合是否冲突、安装后会改什么；缺少本地、可审阅的选择与规划层。
- **独特之处**：把“发现→选择→校验→ immutable 计划→人工审查”做成只读、可审阅的本地流程，且明确不让 AAS 自己排序或推荐，决策权留给 agent 与用户。
- **为什么有价值**：它把 Agent Skill 从‘复制提示词’提升为可管理的依赖组合问题，暴露出选择、校验、规划、回滚这些产品必须回答的环节。
- **与你的关系**：当下：读它的 compose_stack/plan 流程，理解 Agent Skill 组合的产品化设计。未来：做 Skill 选择/推荐功能时，可直接借鉴它的‘只读校验 + 人工审查’边界。
- **建议动作**：30 分钟内：本地安装 CLI，对其 catalog 跑一次 compose_stack 校验一个 3–5 个技能的小组合，记录校验输出与失败原因。
- **Star 原因假设**：假设：Skill 生态早期，开发者急需一个可分类、可本地检索的大目录作为入口，支持信号是 2445+ skills 与 CLI/MCP/Workbench 多层交付；假设：Codex/Claude Code 用户增长带动‘把技能管理起来’的需求，支持信号是 topic 覆盖 claude-code、codex-cli、cursor、gemini-cli
- **风险/限制**：README 声明其为独立社区项目，并引用 Google 产品名，存在品牌与兼容性声明风险；功能面极广（CLI、MCP、catalog、plugins、Workbench、installer），初版学习曲线可能陡；‘2445+ skills’的自述数字无法仅凭 README 验证质量，可能存在低质技能混入
- **判断置信度**：medium

### 2. initializ/forge · 74.5/100
https://github.com/initializ/forge

- **一句话**：Forge 是 Anthropic Agent Skills 标准的开源运行时：写一个 SKILL.md，编译成可移植、加固的 agent，部署到容器、K8s、CI 或 A2A 端点。
- **解决的问题**：Agent Skill 目前多绑定在特定 coding assistant 客户端，难以把同一份技能资产带到自有机房、气隙环境或 CI 里执行。
- **独特之处**：把 SKILL.md 编译为可部署 agent 运行时，默认出站连接、egress allowlist、结构化审计日志，强调‘在你自己的基础设施上运行’。
- **为什么有价值**：它回答了一个产品关键问题：Skill 是提示词资产还是可部署制品？Forge 把答案推向‘可编译、可加固、可审计的运行时’。
- **与你的关系**：当下：用 forge try 体验一次工具调用与 egress 检查的内联展示。未来：设计需要自托管/合规的 Agent 产品时，可参考其安全默认值与审计日志结构。
- **建议动作**：30 分钟内：安装 Forge 跑 `forge try`，观察一次 tool 调用与 egress allowed 的完整链路，并记录其审计日志字段。
- **Star 原因假设**：假设：企业自托管 Agent 需求推动关注，支持信号是 topics 含 enterprise-ai、local-ai-agents、secure-ai；假设：'Anthropic Agent Skills 标准运行时'定位借势标准热度，支持信号是 description 明确绑定该标准
- **风险/限制**：开 issue 数偏高（120），提示早期稳定性与需求堆积；星标增长缓慢（约 0.5/天），生态采用度尚未验证；‘编译到可移植 agent’概念较重，README 承诺与实际上手体验可能不一致
- **判断置信度**：medium

### 3. socai-io/jev-social · 74.0/100
https://github.com/socai-io/jev-social

- **一句话**：Jev × socai 的 Agent Skill + 本地 demo：由 agent 逐步选择操作，在真实 Chrome 中对 Instagram/TikTok/LinkedIn 做取证式研究，产出带引用的报告。
- **解决的问题**：社交平台研究多为黑盒抓取或不可复现的总结，缺少‘每步操作可回溯、证据来自真实浏览器’的可信研究流程。
- **独特之处**：把‘agent 选择下一步 → socai 在本地真实浏览器执行 → 结果回传 agent’做成可记录的操作历史，强调 typed routing 与 cited reports。
- **为什么有价值**：它是‘computer-use + 研究 Agent’的可运行小样例，正好示范如何把浏览器证据、操作日志与引用拼成一个可审阅的研究产物。
- **与你的关系**：当下：跑本地 demo，观察 agent 每一步选了什么操作、证据如何回传。未来：做社交媒体/竞品研究类 Agent 时，可复用其‘操作历史 + 引用报告’的产物结构。
- **建议动作**：30 分钟内：按 README 用本地 Chrome 跑一次 demo，限一个平台一个查询，检查生成的引用报告是否每条结论都有对应操作。
- **Star 原因假设**：假设：'computer-use 做社交研究'是热门交叉话题带来早期关注，支持信号是 topics 同时覆盖 browser-agent、computer-use、osint、socmint；假设：项目在 OSSDrop 获选带来一次性曝光，支持信号是 README 展示 OSSDrop Tool of the Day 徽章
- **风险/限制**：涉及社交平台抓取，可能触碰各平台服务条款与反自动化策略，合规边界不清；README 明确部分演示是早期 routing-only 原型，当前能力与宣传的落差需实测确认；星标基数小（74），社区验证不足，测试信号 README 中 has_tests=false
- **判断置信度**：medium

### 4. nguyenvanphituoc/shapeup-sdlc-plugin · 69.5/100
https://github.com/nguyenvanphituoc/shapeup-sdlc-plugin

- **一句话**：把 Shape Up 生命周期（idea→pitch→build→eval→ship）做成 Claude Code 插件，用 PreToolUse hook 硬拒绝越权写入、缺工单派发与自我汇报式完成。
- **解决的问题**：Agent 常绕过 spec、越权改文件、自称完成；靠提示词约束没用，需要一个运行时门禁来强制流程。
- **独特之处**：用 schema 校验的 WorkOrder + PreToolUse hook 把‘不能做’变成运行时拒绝，而非在提示词里请求；进度从测试产物推导而非自报。
- **为什么有价值**：它提供了一套‘Agent 工作流可靠性’的具体工程范式：哪里该硬门禁、哪里该保持建议，是设计可靠 Agent 产品时绕不开的讨论。
- **与你的关系**：当下：读它的 hook 拒绝样例，理解哪些规则值得硬编码。未来：做需要审计或合规的 Agent 工作流时，可复用‘产物推导进度 + 硬拒绝’思路。
- **建议动作**：30 分钟内：安装该插件，跑一次让 worker 写入 scope 外文件的请求，确认 hook 确实拒绝并记录拒绝信息。
- **Star 原因假设**：假设：Agent 可靠性是当前痛点，但项目太新且零推广，支持信号是 3 star 却高度相关 topics；假设：Shape Up + Claude Code 的组合题材吸引小众方法论人群，支持信号是 README 反复强调‘gate 不能被说服绕过’
- **风险/限制**：几乎无社区验证（3 star，0 fork），生产可用性未知；部分 gate（如 board-green）被标注为 advisory，硬性与建议的边界会影响可靠性预期；仅面向 Claude Code 插件生态，通用性有限
- **判断置信度**：low

- **为什么有价值**：它把‘技能可移植性’作为第一性产品问题，并示范如何诚实地标注哪些 harness 只是工程候选，这对学习产品定位与信任设计很有价值。
- **与你的关系**：当下：在 Claude Code 里装一次 marketplace 并安装一个 pack，观察 canonical 与 adapter 的分层体验。未来：设计跨平台技能分发时，可参考其 canonical/adapter 分层与版本语义说明。

- **风险/限制**：README 明显含营销与赞助成分，需与真实可用性分开评估；其他 harness 仅列为‘工程候选’，跨工具承诺可能被高估；版本语义存在 display version 与 npm package version 分离，可能造成使用困惑
- **判断置信度**：medium

## 今日重点

重点：sickn33/agentic-awesome-skills。目标用户：把 Claude Code / Codex / Cursor 当主力开发工具、已被大量 Skill 淹没的进阶开发者。待办任务：从 2000+ 技能中挑出当前项目真正需要的一小组，并知道安装后会发生什么。旧替代方案：手动搜 GitHub topic、复制 SKILL.md，或用纯 awesome-list 目录。价值主张：本地只读 catalog + agent 自主选择 + compose_stack 校验 + immutable 计划 + 人工审查。AI 是否必要：选择与规划需要语义判断，是必要的；但排序/推荐被有意交给 agent 与用户，说明作者认为‘替用户决策’不是价值点。核心指标：可审阅计划生成率、校验失败可解释率、安装后人工接受率。主要风险：目录质量参差、功能面过宽导致首用复杂、品牌与兼容声明风险。作品集衍生：做一个‘Agent Skill 组合体检器’，输入项目描述，输出技能组合、冲突点与安装影响预览，用它的 compose_stack 思路做只读校验层。
