## 今日重点

重点拆解 sickn33/agentic-awesome-skills。目标用户是同时使用 Claude Code、Codex、Cursor 等编码 agent 的开发者与 AI 产品经理，他们面对 2400+ 技能却不知道选哪些、如何组合、变更前如何验证。待办任务是：给定当前项目，选出合适技能集合，验证兼容性，生成可审计的变更计划。旧替代方案是手动翻 GitHub topic、复制粘贴 SKILL.md、凭感觉组合，缺少一致性和可回滚性。价值主张是把“选择”交给 agent，把“只读校验”交给 compose_stack，把“计划与持久化”交给 aas CLI，人类只在最后评审，从而降低认知负担。AI 是否必要：在本场景中 AI 更适合做选择与解释，但验证与计划不应依赖模型判断，因此 AI 必要但必须被工具约束。核心指标可以是：生成可用 aas-stack 的时间、人类返工次数、技能冲突检出率。主要风险是技能规模大导致质量不可控、apply/recovery 仍属实验性、以及 README 中大量营销式表述可能掩盖实际可用边界。一个作品集衍生想法：做一个“我的 30 分钟 agent 技能栈”小项目，选定 3 个技能，用 compose_stack 验证，输出 aas-stack.json 和变更前计划文档，并附一次回滚演练。
