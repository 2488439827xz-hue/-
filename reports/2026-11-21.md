# AI GitHub Radar · 2026-11-21

今天的候选高度集中在 Agent Skill 目录与合集，数量多但同质化明显。对 AI 产品管理学习者，最值得看的不是又一个技能清单，而是能帮助判断技能质量、安全与工作流设计的项目。建议优先拆解 NVIDIA/SkillEvaluator：它把“技能”当作产品来评估，直接对应质量门、基准和 CI 设计。其次看 sickn33/agentic-awesome-skills 的 AAS Core，理解技能发现、选择与计划预览的信任边界；再看 squirrelscan 与 youtube-research-skills，分别代表“确定审计工具 + Agent”和“垂直研究工作流 + 商业 MCP”的产品形态。aubergine 想法新颖但社区信号极弱、无许可证，暂不宜投入。整体质量中上，但要注意大量 Star 增长仅为首次观测代理，不能当作真实趋势结论。

## 今日项目

### 1. NVIDIA/SkillEvaluator · 81.0/100
https://github.com/NVIDIA/SkillEvaluator

- **一句话**：面向 AI Agent 技能与插件的多层级评估框架，覆盖质量门、安全扫描、harness 兼容性、语义重叠检测、合成评测集生成和真实 Agent 行为评估，并提供可复用 CI 模板。
- **解决的问题**：Agent 技能数量爆炸后，团队缺少统一方法判断技能是否安全、有效、可组合，也难以把评估接入日常开发流程。
- **独特之处**：不只做技能目录，而是评估技能对 Agent 行为的实际影响，并给 CI 模板；把“技能”从内容资产变成可回归测试的软件制品。
- **为什么有价值**：对 AI 产品经理而言，这是少见的把技能质量、安全与评测指标产品化的项目；可迁移到任何 Agent 功能的上线门禁设计。
- **与你的关系**：当下用途：学习如何定义技能质量门、安全扫描项和行为评测指标，反推自己团队的 Agent 上线检查清单。未来用途：若你负责 Agent 平台或技能市场，可借鉴其评估维度设计审核流程与信任分层。
- **建议动作**：30 分钟内通读 README 与 docs 中的评估层级，列出你最关心的 5 个质量/安全检查项，整理成一页“Agent 技能上线检查清单”草稿。
- **Star 原因假设**：NVIDIA 品牌与官方文档带来关注度；Agent 技能治理与安全是当前团队痛点，评估框架稀缺；提供 CI 模板降低接入门槛，易被转发
- **风险/限制**：README 摘录为空，当前证据不足以判断安装与使用体验；评估框架本身较复杂，短期难独立跑通；高度依赖被评估技能的运行环境，结果可复现性需验证
- **判断置信度**：medium

### 2. sickn33/agentic-awesome-skills · 74.5/100
https://github.com/sickn33/agentic-awesome-skills

- **一句话**：3000+ 可安装 SKILL.md 技能库，配套 AAS Core 支持本地目录发现、Agent 自主选择、栈校验和计划预览；提供 CLI、MCP 与插件。
- **解决的问题**：Agent 技能分散且难以审查，用户需要一个可发现、可检查、可固定技能集合的本地目录。
- **独特之处**：不只为技能排名，而是强调“Agent 自己选技能 + 变更前预览计划”的信任边界；技能库与执行核心分离。
- **为什么有价值**：提供了 Agent Skill 产品的关键交互原型：发现、选择、预览、应用四段式，是理解技能市场与 Agent 协作机制的好样本。
- **与你的关系**：当下用途：观察它如何设计技能目录信息架构与计划预览，做竞品或参考。未来用途：若做企业技能库，可借鉴“Agent 选择但人审计划”的权限模型。
- **建议动作**：30 分钟内浏览 aaskills.tech/core 文档，画出“发现—选择—预览—应用”流程，并标注哪一步需要人工确认。
- **Star 原因假设**：3000+ 技能数量与多 IDE 兼容带来收藏动机；CLI/MCP/插件多入口降低试用门槛；技能名称与热门编码 Agent 绑定，易获搜索流量
- **风险/限制**：部分技能为导入内容，许可证与质量参差；npm 发布暂停，安装路径可能变化；Apply 与恢复仍为实验性，信任边界需谨慎
- **判断置信度**：medium

### 3. squirrelscan/squirrelscan · 73.5/100
https://github.com/squirrelscan/squirrelscan

- **一句话**：面向编码 Agent 的网站 QA 工具，350+ 审计规则覆盖 SEO、性能、安全、可访问性与 Agent 体验，可通过 CLI、MCP、云端或 Agent 内使用并给出修复建议。
- **解决的问题**：网站质量审计通常依赖多个人工工具与人工判断，编码 Agent 缺少确定性反馈回路来验证修复效果。
- **独特之处**：把确定性审计与 Agent 修复循环结合，形成“审计—修复—复审计”的闭环，而不是让 LLM 自行猜测问题。
- **为什么有价值**：展示了 AI 产品中“确定性工具 + Agent 判断”的合理分工，是评估 Agent 可靠性的具体案例。
- **与你的关系**：当下用途：观察如何设计审计评分与修复建议，理解 Agent 与工具协作的评估闭环。未来用途：可借鉴到内容质量、代码质量等需要确定性与生成结合的审核产品。
- **建议动作**：30 分钟内在本地对一个静态站点跑一次 squirrel 审计，记录评分变化与 Agent 修复建议，整理成一段评估笔记。
- **Star 原因假设**：网站 QA 是开发者高频刚需，SEO/性能/安全规则易理解；演示 GIF 展示从 F 到 A，传播性强；MCP 与多 Agent 安装入口带来曝光
- **风险/限制**：审计规则的真实覆盖与误报率未在证据中体现；云端与本地 MCP 的安全边界需自行确认；无测试信号，规则扩展性需看文档
- **判断置信度**：medium

### 4. TubeLabHQ/youtube-research-skills · 73.0/100
https://github.com/TubeLabHQ/youtube-research-skills

- **一句话**：面向 YouTube 研究的 Agent 技能集，覆盖异常视频发现、细分市场验证、竞品研究、评论挖掘、标题与缩略图概念、脚本拆解和赞助线索。
- **解决的问题**：内容研究者与创作者需要把分散的 YouTube 数据分析方法固化为可执行工作流，而不是每次从头拼 prompt。
- **独特之处**：把“专家判断 + 工具数据 + 报告产出”封装成多个研究角色，强调每个数字可追溯来源。
- **为什么有价值**：是垂直行业技能产品的清晰样本：商业模式（TubeLab MCP）与开源技能结合，适合研究技能如何绑定数据服务。
- **与你的关系**：当下用途：学习如何把研究 SOP 拆成多个角色技能，并设计可追溯的数据引用。未来用途：可迁移到你所在行业的“研究型 Agent 技能包”设计。
- **建议动作**：30 分钟内选一个技能（如 niche 验证），记录其输入、工具调用、输出报告结构，画成单页流程图。
- **Star 原因假设**：YouTube 创作者与营销人群基数大，痛点明确；绑定 TubeLab MCP 提供真实数据，胜过纯 prompt 库；多 Agent 兼容安装命令降低试用门槛
- **风险/限制**：依赖第三方 TubeLab MCP 与账号/OAuth，长期可用性受制；缺少安全说明与测试信号；研究结论质量依赖底层数据源覆盖
- **判断置信度**：medium

### 5. meatgarden/aubergine · 61.5/100
https://github.com/meatgarden/aubergine

- **一句话**：浏览器画布式终端编排器，可并排运行多个编码 Agent，保留终端会话，并展示哪个 Agent 在等待、处于哪一步、产出了什么。
- **解决的问题**：多 Agent 并行时，人难以同时掌握各终端的进度、等待状态与产出，切换成本高。
- **独特之处**：把多 Agent 运行状态做成可视化工作流看板，并强调本地运行与终端持久化。
- **为什么有价值**：虽然项目很小，但它触及多 Agent 协作的“人机接口”问题，适合思考 Agent 可观测性与控制面设计。
- **与你的关系**：当下用途：作为多 Agent 编排交互的灵感来源，观察其状态模型。未来用途：若设计 Agent 工作台，可参考其“运行—按步骤—工作流”三种视图。
- **建议动作**：30 分钟内阅读 README 的截图与启动步骤，画出它的状态字段（等待/运行/待确认/完成）与用户操作之间的关系。
- **Star 原因假设**：多 Agent 并行是热门话题，可视化画布有传播性；安装脚本与两分钟演示降低体验门槛；话题标签覆盖多 IDE 与 Agent，易被搜索命中
- **风险/限制**：仅 4 星、无许可证，项目可持续性与使用授权不明确；依赖 tmux、Node、pnpm，环境要求限制试用；安全说明缺失，本地运行仍需信任脚本
- **判断置信度**：low

## 今日重点

NVIDIA/SkillEvaluator 值得今天优先拆解。目标用户：负责 Agent 平台、技能市场或内部 Agent 工具链的工程与产品团队。待办任务：在技能数量快速增长时，判断某个技能是否安全、是否与现有技能语义重叠、是否真正改善 Agent 行为，并把这些检查嵌入 CI。旧替代方案：人工看 README、凭经验抽查、零散安全脚本，缺少统一质量门和行为回归。价值主张：把技能当作可测试制品，提供质量门、安全扫描、兼容性检查与真实 Agent 行为评估。AI 是否必要：评估“技能对 Agent 行为的影响”必须运行 Agent，因此 AI 是评估对象也是评估手段；但确定性检查仍应保留，形成混合评估。核心指标建议：技能通过率、误报率、CI 接入成本、技能变更后行为回归捕获率、平均评估耗时。主要风险：框架复杂、复现成本高、README 证据不足、评估自身可能被“刷分”。作品集衍生想法：做一个“Agent 技能上线门禁”迷你项目，选 3 个技能，定义质量与安全规则，跑一次前后对比评估，输出一页评估报告与决策建议。
