### 1. ryuxdsgn/design-intelligence · 76.8/100
https://github.com/ryuxdsgn/design-intelligence

- **一句话**：RYUX 是一套面向设计决策的 Agent Skill，要求 AI 在生成 UI 前先澄清产品上下文、区分事实与假设、记录决策并验证结果。README 提供了同题对比基准，展示有/无技能时 Agent 在追问、事实假设和状态覆盖上的差异。
- **解决的问题**：AI 生成 UI 很快，但常把需求未给出的事实当成已知，跳过状态与异常路径，产品经理很难看出哪些是假设、哪些是真实决策。
- **独特之处**：把“先理解再设计”做成可安装的 Agent 工作流，并用对比基准展示行为差异，而不是只提供提示词模板。
- **为什么有价值**：它展示了 Agent 产品中一个关键设计点：如何用技能约束减少隐式决策，并把假设显式化。对学习 Agent 工作流和评估设计的读者有直接参考价值。
- **与你的关系**：当下用途：用来观察 Agent Skill 如何改变模型行为，并学习如何设计对比基准。未来用途：可作为你设计 AI 产品评审流程或作品集案例的参考框架。
- **建议动作**：打开 README 中的基准对比 GIF 和文档，记录 RYUX 让 Agent 追问的三个问题，以及它如何标注假设；用一页笔记整理成“Agent 设计评审检查清单”。
- **Star 原因假设**：设计类 Agent Skill 供给较少，切中 UI 生成中“幻觉事实”的痛点；项目附带可视化对比基准，便于传播和讨论；早期访问版本持续更新，可能吸引设计工具用户关注
- **风险/限制**：Star 数较少，社区验证有限；README 中的对比基准是作者自述，尚未看到独立复现；项目处于早期访问阶段，接口与行为可能变化
- **判断置信度**：medium

### 3. hanzohanzhe/Grandet · 66.5/100
https://github.com/hanzohanzhe/Grandet

- **一句话**：Grandet 提供 Agent Skill 和远程 MCP，用于查询各模型 API 的挂牌价格与免费额度，并帮助 Agent 连接最低价提供商。它强调只按挂牌价排序，不评价供应商质量。
- **解决的问题**：模型 API 价格与免费额度分散在官方、推理商和转售站点，开发者在 Agent 中比价成本高。
- **独特之处**：把比价与免费额度查询做成免登录的远程 MCP 和 Agent Skill，可直接在对话中调用。
- **为什么有价值**：它示范了一个轻量、可嵌入 Agent 的外部数据服务，对理解 MCP 工具设计和 Agent 调用外部服务的信任边界有帮助。
- **与你的关系**：当下用途：观察 Agent Skill 如何封装一个简单查询服务，以及如何声明“只比价、不做推荐”的边界。未来用途：可借鉴到其他价格/目录类 Agent 工具的产品设计。
- **建议动作**：在任意支持远程 MCP 的客户端添加 https://grandet.ai/mcp，查询一次模型价格，并检查返回结果是否标注观察时间与计价单位。
- **Star 原因假设**：模型 API 比价是开发者高频需求；免登录远程 MCP 降低了试用门槛；“找最便宜 API”的表述容易在社交平台传播
- **风险/限制**：许可证状态为 NOASSERTION，使用条款不清晰；README 缺少使用示例与测试信号；比价数据依赖第三方站点挂牌，准确性难以独立验证
- **判断置信度**：medium

## 今日重点

重点看 ryuxdsgn/design-intelligence。目标用户是使用 AI 生成 UI 的产品设计师与产品经理；待办任务是“在生成界面前把产品上下文、事实与假设说清楚”。旧替代方案是依赖提示词或人工设计评审，容易在生成后才发现隐式假设。价值主张不是生成更多 UI，而是减少静默决策，并把假设显式化。AI 在这里是必要的，因为需要 Agent 在生成过程中主动追问、记录并验证；但技能本身只是行为约束，效果仍依赖模型与执行环境。核心指标可设为：生成前追问率、未提供事实被误标为已知的数量、异常状态覆盖率、评审返工次数。主要风险是对比基准由作者自述、样本量小、早期访问版本不稳定。一个作品集衍生想法：选一个你熟悉的 AI 产品需求，分别用普通提示词和 RYUX 式流程生成界面，记录假设数量与状态覆盖差异，写成一页对照分析。
