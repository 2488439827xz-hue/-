### 1. lennney/stop-that-shit · 78.5/100
https://github.com/lennney/stop-that-shit

- **一句话**：面向 Codex/Claude Code 等编码 agent 的 Hook + Skill Guard，用 SCOPE/HASH/INTENT/THRASH 规则拦截范围膨胀、无用校验和、越权修改与任务打转。

- **为什么有价值**：它把“agent 过度执行”这一高频隐性成本变成可观察、可规则化的控制点，适合作为 AI 产品经理理解 agent 安全边界与工作流设计的具体样本。
- **与你的关系**：当下可用于体验 agent guardrail 的产品化形态；未来可借鉴到你的 agent 产品需求评审与验收标准中。
- **建议动作**：30 分钟内按 README 安装到 Codex 或 Claude Code，构造一个“只导出 CSV”的小任务，观察 guard 是否拦截额外 checksum，并记录触发日志。
- **Star 原因假设**：Star 增长可能与开发者对 agent 过度执行、token 浪费的普遍痛点共鸣有关；支持信号是 README 用大量真实场景描述 SHIT 四类问题；可能受益于 Codex/Claude Code 生态热度与 agent-skills 话题曝光；支持信号是 topics 覆盖 codex、claude-code、guardrails
- **风险/限制**：README 缺少正式文档与测试信号，规则在复杂任务上的误拦截率未知；项目创建时间较短，长期维护与跨 agent 兼容性需观察；Hook 侵入式运行，若配置不当可能阻断正常任务
- **判断置信度**：medium

## 今日重点

stop-that-shit 值得作为重点项目拆解。目标用户：使用 Codex/Claude Code 等编码 agent 的开发者与 AI 产品经理。待办任务：让 agent 完成当前请求，同时不产生无用途的额外工作并保持用户划定的权限边界。旧替代方案：在 AGENTS.md 里不断追加“不要乱改”“别过度设计”等提示，规则越堆越长且不可执行。价值主张：把范围控制从软性提示升级为可运行的 Hook 与 Skill 拦截，并给出前后对比案例。AI 是否必要：必要性体现在需要理解任务语义与请求边界，纯静态 lint 难以判断“这个 checksum 是否被下游读取”；但规则本身的执行可确定性化。核心指标：误拦截率、有效拦截次数、每任务 token 节省、用户手动纠正次数。主要风险：规则误伤正常任务、跨 agent 兼容性、缺少测试与正式文档导致信任不足。作品集衍生想法：做一个“agent 过度执行审计”小工具，对一段 agent 会话记录标注 SCOPE/HASH/INTENT/THRASH 四类问题并给出可配置的拦截建议。
