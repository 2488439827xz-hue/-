### 2. Gentleman-Programming/gentle-ai · 75.8/100
https://github.com/Gentleman-Programming/gentle-ai

- **一句话**：Gentle-AI 是给已有编码 agent（Claude Code、Cursor、Codex、OpenCode 等 16 种）加装的确定性工程环境：持久记忆、Organic-Driven Development 工作流、精选 skills、MCP servers、persona，以及可选的有界审查，目标是让 agent 有记忆、有流程、有证据。
- **解决的问题**：编码 agent 写完代码后“失忆”，不了解项目上下文，也无法证明自己做了什么，导致人必须逐行审查、重复交代背景。

- **为什么有价值**：这是少见的“横切层”产品思路：不卷模型、不卷 IDE，而卷 agent 之间的通用工程体验。对理解 agent 产品的差异化定位、记忆与证据链设计很有参考价值。
- **与你的关系**：当下用途：拆解它如何定义“持久记忆”“工作流”“证据”三个卖点，以及如何在 16 个 agent 上做兼容。未来用途：为你自己的 agent 产品设计通用中间层或记忆模块时，直接复用这套定位框架。
- **建议动作**：30 分钟内阅读 README 与 docs/quickstart.md、docs/intended-usage.md，列出它声称解决的三个痛点及对应机制，并标出哪些是已有（README 断言）与哪些需要你亲自验证。
- **Star 原因假设**：假设：多 agent 兼容 + 无锁定契合当下开发者对工具碎片化的焦虑，带来自然口碑。支持信号：README 明确 16 agents、no agent lock-in，topics 覆盖 claude-code/cursor/codex/opencode；假设：视觉化品牌与明确 slogan（deterministic engineering environment）提升了传播效率。支持信号：README 含 banner、badges、多个 docs 入口与网站；假设：周级 337 star 增长与持续 push 相关。支持信号：momentum 显示 7 天 +337 stars，pushed_at 与 updated_at 为当日

### 3. billy-enrizky/openbrowser-ai · 72.8/100

## 今日重点

重点项目：sickn33/agentic-awesome-skills（AAS Core）。目标用户：使用 Codex/Claude/Cursor 等编码 agent 的开发者与搭平台的技术 PM。待办任务：在真实项目里选出一组合适、可复核、可复用的 agent skills，并留下可审查的计划，而不是凭记忆拼 prompt。旧替代方案：手工维护的 awesome-list、个人笔记或每次让 agent 现编指令。价值主张：把 skill 发现、选择、校验、计划生成拆成清晰的只读与写入两段——AAS 不做排序推荐，由 agent 选择，MCP 只读 compose_stack 在内存中校验，再由 CLI/客户端落成 aas-stack.json 和不可变计划。AI 是否必要：必要，因为“读懂项目 → 从 2400+ skills 中选”依赖语义理解，传统规则难以覆盖。核心指标：skil 选择被人工复核通过的比例、生成计划的实际采纳率、从校验到计划的人工返工次数。主要风险：目录规模大但单 skill 质量参差不齐；apply/recovery 仍是 experimental；强绑定特定 agent。作品集衍生想法：做一个最小“skill 治理”demo——给定一个小项目，用只读校验生成技能栈清单与不可变计划，并记录 3 次选择被推翻的原因，形成一份可展示的 skill 选型决策日志。
