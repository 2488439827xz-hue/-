## 今日项目

### 1. mvschwarz/openrig · 75.0/100
https://github.com/mvschwarz/openrig

- **一句话**：用 YAML 定义一个持久化多 Agent 团队，把 Claude Code、Codex 等 harness 组织成有角色、共享上下文和任务归属的“rig”，并提供 TUI 观察各席位运行状态。
- **解决的问题**：单个编码 Agent 的会话是一次性的、上下文易散落；多 Agent 并行时缺少角色分工、任务归属和统一观察面，团队协作难以复现。
- **独特之处**：不只是再包一层 Agent，而是把多个 harness 当作被编排对象，强调持久席位、共享上下文地址和 lead agent 协调，并提供可视化 TUI。
- **为什么有价值**：它把“多 Agent 系统”从概念落到可运行的团队配置：YAML 定义 + 角色 + 状态面板，正好对应 AI 产品经理需要理解的编排层抽象，而不是又一个提示词合集。
- **与你的关系**：当下：用它的 quickstart 了解一个多 Agent 团队的最小配置长什么样，体会角色、上下文与交接的设计。未来：把这种“lead + specialist + 共享上下文”的结构迁移到你的产品或工作流设计中。
- **建议动作**：30 分钟内读 docs/reference/quickstart.md，复制一份示例 rig 的 YAML，改两个角色名称与职责描述，画出你设想的一个产品工作流团队图。
- **Star 原因假设**：多 Agent 编码是 2026 年热点，项目主题与 Claude Code/Codex 生态强绑定，容易获得关注；提供 TUI 演示 GIF 与一键 npx 安装路径，降低首次尝试门槛；作者以“AI civilization experiments”叙事吸引探索型开发者
- **风险/限制**：README 声明 apply 与恢复机制仍属实验性，生产可用性未验证；项目较新（2026-04 创建），open issues 较多，长期维护不确定；多 Agent 编排容易产生不可预期的成本与调试复杂度
- **判断置信度**：medium

### 2. JiamingShi-JsPhys/chelate-shell · 73.5/100
https://github.com/JiamingShi-JsPhys/chelate-shell

- **一句话**：把 19 个科研与工程技能通过四层路由串成确定性流水线，强调阶段顺序、输出落位与在不可逆步骤前停止。
- **解决的问题**：技能生态里每个技能只解决单点问题，Agent 仍需自行决定调用顺序与输出归属，导致上下文污染、文件版本混乱和看似自信的错误。
- **独特之处**：技能以真实算法实现而非提示词模板（SymPy、RDKit、OpenCV、R 等），并用 router 强制四区工作区、阶段门禁和不可逆步骤前停机。
- **为什么有价值**：它给出了“技能编排 + 安全边界”的具体范式：路由、阶段、门禁、停机点，这些正是 Agent 工作流产品化时最容易被忽略的部分。
- **与你的关系**：当下：学习它的四层路由与工作区分区设计，作为你设计 Agent 流水线的参照。未来：把“不可逆步骤前停机”这一模式写入你自己的 Agent 产品安全规范。
- **建议动作**：30 分钟内读 README 的 Why Chelate Shell 与安全边界两节，画一张四区工作区 + 阶段门禁的流程图，标注你认为最该加停机点的步骤。
- **Star 原因假设**：星标仅 11，尚未形成增长；可能是小范围分享或作者自荐带来的早期关注；话题组合（科研 + Agent 编排 + DSH 插件）垂直，受众窄；作为证据：当前无可靠的增长信号，不能视为热门
- **风险/限制**：社区信号极弱，缺少外部验证与贡献者；项目非常新且概念较多，文档密度高，30 分钟只能理解框架；科研技能涉及公式、化学与统计计算，正确性需专业复核，README 也提示仅供辅助
- **判断置信度**：medium

### 3. NVIDIA/SkillEvaluator · 67.5/100
https://github.com/NVIDIA/SkillEvaluator

- **一句话**：面向 AI Agent 技能的多层评估框架，包含质量门禁、语义重叠检测、合成评估数据集生成，以及衡量技能如何影响 Agent 行为的实时评估。
- **解决的问题**：技能库快速膨胀后，缺少系统方法判断技能质量、重复度与真实效果，团队只能凭感觉挑选技能。
- **独特之处**：把“技能”本身当作评估对象，覆盖静态质量、重叠检测、合成数据与在线行为评估，并带有安全扫描相关话题标签。
- **为什么有价值**：在技能数量爆炸的当下，评估与筛选才是产品决策的核心；这个项目提供了可借鉴的评估维度框架，即使不直接跑也能用于设计自己的技能准入标准。
- **与你的关系**：当下：把它当作技能评估维度的清单，对照检查你收集的技能是否重复、是否可验证。未来：用它的分层思路设计你产品的技能市场审核机制。
- **建议动作**：30 分钟内浏览仓库目录与 docs 入口，列出一张“技能准入评估表”，包含质量、重叠、行为影响三类指标各两条。
- **Star 原因假设**：NVIDIA 品牌背书带来可信度与曝光；技能评估是当前技能生态的空白点，需求真实存在；单日约 329 星的增速可能来自发布公告或社区传播（假设，缺少直接证据）
- **风险/限制**：候选证据中的 README 摘要为空，安装与使用细节无法从证据确认；评估框架通常依赖较多依赖项与算力，实际跑通成本未知；技能行为评估的指标定义若不透明，结论可能被误读
- **判断置信度**：low

### 4. VoltAgent/awesome-agent-skills · 64.0/100
https://github.com/VoltAgent/awesome-agent-skills

- **为什么有价值**：对学习者而言，它是低成本获取高质量技能样例的入口；对产品经理而言，可以借它观察技能生态里真实的分类与来源结构。
- **与你的关系**：当下：挑 3 个与你工作场景相关的技能，读它们的 SKILL.md 结构。未来：把它当作竞品技能市场的样本集，分析分类与筛选维度。

- **Star 原因假设**：Awesome 列表形式天然易传播，且技能话题正热；VoltAgent 已有社区与 Discord 导流；README 明确“非批量生成”形成差异化卖点
- **风险/限制**：本质是索引列表，缺少对技能实际效果的验证；README 含赞助商内容，需区分推广与内容；收录规模大，质量一致性依赖人工挑选，难以逐条核实

## 今日重点

重点看 mvschwarz/openrig。目标用户是已经在用 Claude Code 或 Codex、但被多终端会话淹没的独立开发者与小团队。待办任务是：让多个编码 Agent 按角色协同完成一个仓库里的连续改动，并保持上下文与任务归属清晰。旧替代方案是手动开多个终端、复制粘贴上下文，或用单 Agent 串行执行，结果不可复现、交接靠人脑。价值主张是“用 YAML 定义团队、一条命令启动、一个 TUI 观察”，把多 Agent 从演示变成可管理的系统。AI 是否必要：是，因为协调者需要理解自然语言目标并动态分配任务，但要注意真正的价值在编排与状态管理，而非模型本身。核心指标可设为：任务一次通过率、人工干预次数、上下文丢失导致的返工率、每任务成本。主要风险是多 Agent 成本与调试复杂度上升，以及 apply/恢复仍属实验性。作品集衍生想法：做一个“多 Agent 工作流设计卡片”，用你自己的一个产品需求，画出 lead agent、specialist 角色、共享上下文地址与停机点，并用 openrig 的 YAML 结构表达出来。
