## 今日项目

### 1. kajisho5/ffmpeg-skill · 83.0/100
https://github.com/kajisho5/ffmpeg-skill

- **一句话**：把 FFmpeg 封装成 42 个可被编码 Agent 调用的视频编辑工具，并提供 MCP 通道；支持裁切、字幕、竖屏重构图、响度归一与平台导出。
- **解决的问题**：非视频专业的 AI 产品经理或开发者，想把“剪辑一段素材并验证输出”交给 Agent，但直接写 FFmpeg 命令门槛高、参数易错、缺少可检查契约。
- **独特之处**：不是又一个视频生成模型，而是把传统确定性工具做成 Agent 可读、可执行、可自检的能力层，强调本地运行、无需云密钥。
- **为什么有价值**：它示范了 Agent Skill 的正确工程形态：机器可读契约、明确工具集、输出可测量、失败可检查。对学习 Agent 产品的人来说，比“提示词大全”更接近真实工作流设计。
- **与你的关系**：当下用途：用它理解“工具型 Agent Skill”如何定义输入输出和验收标准，30 分钟内跑一个竖屏裁切加字幕 demo。未来用途：把这套契约思维迁移到你自己的 Agent 工作流，例如文档处理、数据分析或内容批处理。
- **建议动作**：安装 FFmpeg 后执行 npx ffmpeg-skill，选一段 30 秒素材，让 Agent 完成 9:16 裁切加自动字幕，并记录它如何检查输出时长与分辨率。
- **Star 原因假设**：视频内容创作需求强，把 FFmpeg 能力包成 Agent 工具直接降低使用门槛；支持信号是 README 含多个动图 demo 与 npm 一键入口；本地优先、无需 API Key 的定位契合隐私与成本敏感用户；支持信号是 topics 同时包含 mcp-server、whisper、local 相关标签；首周高 Star 增速可能来自编码 Agent 社区传播；这是假设，当前只有单次 Star 增量快照，不能证明长期热度
- **风险/限制**：依赖本机 FFmpeg 与 Whisper 等环境，跨平台安装失败会直接阻断体验；42 个工具参数多，README 无法证明所有边界场景都被测试覆盖；自动字幕与裁切效果依赖素材质量，营销式 demo 可能高估普适性
- **判断置信度**：medium-high

### 2. NVIDIA/skills · 73.0/100
https://github.com/NVIDIA/skills

- **一句话**：NVIDIA 官方维护的 Agent Skill 目录，覆盖 Physical AI、机器人、仿真、CUDA、RAG 与平台工具，通过 skills CLI 安装到 Claude Code、Codex 等编码 Agent。
- **解决的问题**：企业用户希望 Agent 能正确使用 NVIDIA 生态工具，但官方文档分散、版本与安装路径复杂，Agent 容易给出过时或错误命令。
- **独特之处**：官方验证加每日镜像同步，把“技能治理”做成可发现、可安装的能力目录；NVIDIA Skill Finder 还能反向帮助 Agent 查找技能。
- **为什么有价值**：它提供了 Agent Skill 分发的企业级样本：谁维护、如何验证、如何同步、如何让 Agent 自己找技能。对设计内部技能市场很有参考价值。
- **与你的关系**：当下用途：观察官方如何写技能边界与安装约束，学习“技能发现器”这一元技能设计。未来用途：若你做企业 AI 产品，可借鉴其能力治理与目录同步机制。
- **建议动作**：运行 npx skills add nvidia/skills --skill nvidia-skill-finder --yes，然后让 Agent 推荐一个 RAG 相关技能，并记录它给出的安装理由。
- **Star 原因假设**：NVIDIA 品牌与官方验证背书带来信任与曝光；支持信号是 Apache-2.0 加官方 docs 域名；Physical AI 与机器人是 2026 年热点，技能目录承接了编码 Agent 进入硬件仿真场景的需求；这是假设，缺少搜索来源证据；每日自动同步降低目录过期感，可能提升收藏意愿；支持信号是 README 明确镜像同步流水线
- **风险/限制**：技能分散在各自产品仓库维护，目录本身不保证单个技能质量一致；多数技能面向 NVIDIA 软件栈，非该生态读者上手价值有限；依赖较新的 skills CLI，旧版本存在安装后不可见问题
- **判断置信度**：medium

### 3. sickn33/agentic-awesome-skills · 70.5/100
https://github.com/sickn33/agentic-awesome-skills

- **一句话**：收录 3000 多个可安装 SKILL.md 的技能库，配套 AAS Core 做本地目录检索、Agent 自主选择与计划预览，支持 CLI、MCP 与插件。
- **解决的问题**：Agent 用户面对大量技能文件，缺少统一发现、审阅与本地保留机制，难以知道 Agent 会安装什么、改动什么。
- **独特之处**：不只做清单，还提供“先预览计划再应用”的信任边界；明确说明 Core 不做排名推荐，把选择权交给 Agent 与用户。
- **为什么有价值**：它把技能库问题从“收集多少”推进到“如何审阅与可回滚地应用”，这对 Agent 产品落地很关键，但应用与恢复仍标注为实验性。
- **与你的关系**：当下用途：把它当技能索引用，学习 AAS Core 的计划预览交互。未来用途：借鉴其“目录发现—选择—预览—应用”的状态机来设计内部 Agent 工具市场。
- **建议动作**：按 README 的 GitHub 安装路径装好 AAS Core，仅执行目录搜索与计划预览，不实际应用，截图记录预览里展示了哪些变更。
- **Star 原因假设**：技能数量与多编辑器兼容覆盖面形成规模效应；支持信号是 3000 多个技能与 Claude Code、Codex、Cursor、Gemini CLI 标签；AAS Core 的“可审阅计划”回应当前 Agent 安全焦虑；支持信号是 README 强调 trust boundaries 且 apply 仍为实验性；高 Star 也可能来自早期命名与聚合曝光；这是假设，缺少历史增长数据
- **风险/限制**：npm 发布暂停，安装路径改走 GitHub，新手易卡在环境配置；技能内容来自导入，许可证与归属要求各自不同，商用需逐项核对；应用与恢复为实验性，误改目标文件风险不可忽视
- **判断置信度**：medium

### 4. simota/agent-skills · 67.0/100
https://github.com/simota/agent-skills

- **一句话**：包含 90 个专家 Agent 与 Nexus 编排器，按 Anthropic Agent Skills 规范组织，附带 49 个 Recipes 与 11 个 Skill Packs，覆盖开发、安全、测试、FinOps 等。
- **解决的问题**：编码 Agent 在处理复杂任务时缺少角色分工与编排结构，用户需要可复用的专家角色和任务链，而不是单次提示。
- **独特之处**：用 hub-spoke 编排把多专家 Agent 串成任务链，并提供 make link 跨 CLI 共用同一工作树，强调不覆盖已有技能。
- **为什么有价值**：对学习多 Agent 编排的产品经理，这是可读的结构样本：角色如何拆分、编排层如何调用、跨工具如何安装。Star 少但主题命中度高。
- **与你的关系**：当下用途：阅读 Nexus 与几个专家技能定义，理解多 Agent 任务链的职责边界。未来用途：为你自己的复杂流程设计一个编排层原型。
- **建议动作**：克隆仓库后只运行 make status，查看三个 CLI 目录的链接状态，再读 Nexus 编排器文档，不执行任何写操作。
- **Star 原因假设**：项目偏方法论与本地编排，缺少视频类直观 demo，传播性弱；支持信号是 Star 基数小且日增约 0.5；多 CLI 兼容与规范对齐对重度编码 Agent 用户有吸引力，但受众窄；这是假设
- **风险/限制**：90 个 Agent 的质量与维护成本难以由单个小团队保证；仓库缺少自动化测试信号，编排行为正确性缺少证据；Star 与社区信号弱，遇到问题获得帮助的概率较低
- **判断置信度**：medium

## 今日重点

重点看 kajisho5/ffmpeg-skill。目标用户：需要批量处理短视频、但没有视频工程背景的独立创作者与小团队。待办任务：把一段原始素材在本地变成符合平台规格的成片，并确认输出真的达标。旧替代方案：手写 FFmpeg 命令、用剪映或 CapCut 手动拖时间线、或调用云端视频 API。价值主张：让编码 Agent 用确定性工具完成剪辑并自检，本地运行、无密钥、结果可测量。AI 是否必要：剪辑执行本身不需要大模型，AI 的必要性在于把自然语言意图翻译成工具调用、选择参数并在失败时重试；如果只是固定模板批处理，脚本即可，不必上 Agent。核心指标：单条视频从指令到可发布成品的完成率、人工返工次数、输出规格校验通过率、单条处理耗时。主要风险：本机依赖与跨平台安装、工具参数多导致 Agent 误选、字幕质量波动、demo 效果被高估。作品集衍生想法：做一个“Agent 视频交付质检报告”小工具，对每条输出自动记录时长、分辨率、响度与字幕覆盖率，并用一页看板展示通过率，体现你会定义验收标准而不只是会调工具。
