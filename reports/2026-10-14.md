## 今日重点

creedants/pstack-t3 是今天最值得拆解的项目。目标用户是同时使用多个模型（Claude、Codex、Grok）进行编码的独立开发者或小团队；待办任务是让 AI 写出的每行变更都经过独立模型评审，并在合入前保持可回滚的隔离。旧替代方案是人工 review 或单模型自审，常见问题是审查盲区大、合入冲突难追溯。价值主张是把评审、隔离与合入三个环节工程化为 brigade 协调器，每个单位工作跑在自己的 git worktree 中，只有通过评审的变更才能进入唯一写入主干的队列。AI 在此是必要的：多模型交叉评审本质上需要不同模型家族的独立视角，单靠规则工具无法覆盖代码语义层面的风险。核心指标可观察为：每单位工作从提交到合入的时长、评审发现的真实缺陷数、以及 merge queue 的冲突率。主要风险是社区验证极少、依赖本地 T3 Code 环境、缺少安全边界说明。一个作品集衍生想法是：用一周时间记录 brigade 的 live run 数据，做一个'多模型评审是否真的减少了缺陷'的小型分析仪表板。
