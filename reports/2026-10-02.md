## 今日重点

重点拆解 mcptoon：目标用户是同时使用 Claude Code、Cursor、Codex 等 Agent 并接入多个 MCP 工具/Skill 的开发者与 AI 产品实践者。待办任务是“让 Agent 用上更多工具，同时不被工具描述吃光上下文，并避免在多 Agent 间重复配置”。旧替代方案是手工维护各 Agent 独立配置文件、全量加载 MCP 工具，或用脚本自行裁剪描述。价值主张是零依赖、单配置、跨 Agent 复用，并把工具发现上下文压缩约 90%（README 自称 99.2% 样本值，需自验）。AI 是否必要：工具选择的语义路由确实需要 LLM 能力，但“压缩与统一配置”本身是确定性的工程问题，AI 不是唯一解，这恰是它能落地且可衡量的原因。核心指标可设为：工具发现 token 数、首字节到可用工具的就绪时间、跨 Agent 配置一致率、技能实际调用成功率。主要风险是安全边界不清（本地注入 skill/MCP 的供应链与提示注入）、自称节省比例缺乏第三方验证、项目年轻无历史增速。作品集衍生想法：做一份“Agent 上下文预算仪表盘”原型，量化不同 MCP 配置下的 token 占用与成本，并给出压缩前后对比报告，体现对 Agent 经济性的产品判断。
